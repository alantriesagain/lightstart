# Native probes

One-file programs that decide how light's shared core is written so that scriptc compiles it to a
static binary. `node native/probes/run.js [--scriptc <path>] [p-a …]` reports coverage, builds
each probe natively, runs it, diffs the output against node, and writes `RESULTS.md`. Rerun them on
every scriptc upgrade.

## Decisions (scriptc 0.2.9 and 0.2.10 behave identically on every probe)

| Probe | Outcome | Decision |
|---|---|---|
| p-a-dispatch: `unknown` values dispatched by `typeof`, `instanceof` (module-level classes), `Array.isArray`, identity through `unknown`, handlers invoked with `fn.call(owner, event)`, `Map<unknown, number>` | PASS, except `String(object)` on a checked object (`Object.getPrototypeOf … not supported`) and reading a `Symbol.for` class field through a narrowed value (ICE SC9001) | The core keeps light's value model: values are `unknown`, `html()`/`key()`/… return class instances, `_commitResolved` dispatches with `typeof`/`instanceof`/`Array.isArray`. The `[TPL]`/`[WRAP]` symbol fields are written for compatibility and never read by the core. The last-resort `String(value)` goes through `host.stringify`. Thunks and handlers stay bare functions. |
| p-b-host: a `Host` base whose methods throw, a subclass installed through a module-level variable, opaque `unknown` nodes with identity, a `@typedef` union in a class field, nullable function fields, `Set` of instances, an overridden getter | PASS | The host seam is a class with `configure({ host })`, exactly as designed. |
| p-d-signals: `Dep` non-generic base, `Signal<T>` and `Computed<T>` as sibling subclasses, `Reactive` base class, wave-draining notify, `subscribe` | PASS | M4 signals shape. |
| p-h-queue: a Promise resolved from a field-held resolver and awaited, `Promise.all`, `Array.prototype.sort` with a comparator over a `Map` of instances, try/finally, a config class with function fields set from a partial record | PASS once the comparator's parameters carry `@param` types; inferred, they are `unknown` and the `Map` lookup becomes a deferred throw | The view core's queue and `$updatePromise` compile as written; every callback the core hands to a library method annotates its parameters. |
| p-i-handlers: a subclass instance passed as its base class, boxed to `unknown` by the engine, handed to a handler through `fn.call(owner, event)` and through a direct call | a handler typed with the **subclass** fails ("expected ChangeEvent at $[0], got object") whenever the instance passed through a parameter typed with its base class first; typed with the base class or `unknown` it passes; a direct call of a value that never crossed a base-typed parameter passes | See p-m. The engine asks the host how to call a handler: `host.bindsHandlerThis` is true for the browser and markup hosts (`fn.call(owner, event)`) and false for the terminal host (`fn(event)`, no `this`). |
| p-m-dispatch-unknown: the dispatch path typed `unknown` end to end, narrowing with `instanceof` to read the type | PASS, whether the handler receives the narrowed binding or the original value; the same instance through a `UIEvent`-typed parameter fails | `TElement.handle`, `dispatch` and `Renderer.dispatchFrom` take `unknown` and narrow with `instanceof UIEvent`, so a terminal handler may be typed with the event class it expects (`@key=${(e) => …}` with `e: KeyEvent`). The rule: a class instance keeps its identity through `unknown`, not through a parameter typed with a base class; narrowing a binding with `instanceof` restores it (`paint` narrows a `TNode` before calling `paintInput`), while a conditional on an element access (`kids[0] instanceof TElement ? kids[0] : null`) does not, so narrow a `const` first; the elements `Array.prototype.filter` answers lose it too, so a native test collects elements with a loop that narrows. |
| p-j-map-entries: `for (const [k, v] of map)`, `map.entries()`, `map.forEach`, and the tokenizer's attribute order | destructured for-of and `entries()` PASS; `Map.prototype.forEach` with a callback is SC2011 (no static representation) | Iterate maps with for-of; never `forEach`. |
| p-k-map-union: a string read out of a `Map<string, string>` passed to a method whose parameter is `string | number | boolean | null`, in five forms | PASS | The terminal host boxes static attributes into props as it does. |
| p-l-char-assign: a character read by index, stored on a field by assignment, by `+=`, and by `"" + c` | PASS in isolation; yet in `html/parser.js` the first character of an unquoted attribute value, assigned with `a.value = c` inside the tag state machine, came out empty natively (`padding=2` → `padding=""`) | The parser starts an unquoted value empty and lets the value state append every character; a native test (`native/parts.test.js`) renders static attributes so a regression shows. The trigger is in the surrounding switch, not reproduced yet. |
| p-n-alloc, p-o-subclass-field, p-p-override, p-q-override-order, p-r-virtual-site, p-s-leaf-class: what an object costs natively (run each with `--time`) | a class whose methods are never called allocates in 0.1 µs and reads and writes fields in nanoseconds, like a record; a class whose method is **called anywhere**, with or without subclasses or overrides, allocates in 1 to 4 µs, writes a field in 0.35 µs and takes 0.5 to 0.7 µs per call; `Map` keyed by objects scales linearly with its size (0.3 s for 10k set and get), `Set` of objects does not; `indexOf` over objects is 6× node | This is the native performance ceiling of scriptc 0.2.10 for an object-oriented engine, not of light's design: the harness's typed PoC had the same per-node cost on its small screens. A terminal screen of a few hundred nodes renders in milliseconds; `native/bench.js`'s 10k rows take seconds. Report upstream; revisit on each scriptc release with `native/microbench.js`. |
| the packaged compile (`npm pack` from `dist/`, installed into a scratch app, `scriptc coverage app.js --npm-static @bootstrapp/light`) | a bare `@bootstrapp/light` import is dynamic unless `--npm-static` names the package; compiled that way, three string-index reads in `html/tokenizer.js` and the interface-typed listener binding in the hosts were deferred, though the same files compile fully static in-repo | The tokenizer reads characters with `charAt`; the hosts type the binding as `EventBinding`; the packaged compile is fully static. A consumer builds with `--npm-static @bootstrapp/light`. |
| the harness's `Emitter<T>` (a generic class with methods, in its own module) next to `html/template.js` and `html/parts.js` | `e.listen is not a function` natively; the same class alone, beside `signals/`, `view/core.js`, `html/values.js` or `html/parser.js` works, and a non-generic copy beside `template.js` works | A generic class with methods from one module can lose its methods when the program also holds `html/template.js`; the harness replaced its emitter with nullable callback fields. Light's own generic classes (`Signal`, `Computed`) are exercised by the native tests and the harness; the trigger is not isolated yet (probes p22, p23 and p31 of the harness saw a relative of it in 0.2.9). |
| the terminal tree's children as a linked list (`native/microbench.js`, `native/probes/out/bench-n.js`) | node: create 10k rows 313 ms to 64 ms, reverse 1704 ms to 27 ms; native: 10k create 8.5 s to 3.3 s, reverse 4.6 s to 0.5 s, but 1k create 232 ms to 352 ms and 10k plain appends 104 ms to 288 ms | A field write on an object in the compiler's dynamic representation is a named lookup (`scr_dyn_obj_put` with `strcmp` in the profile), so the four pointer writes of a link cost more than one array push until the scan they replace dominates. The list stays, since it is right on every engine and the screen does not notice; the cost of a field write is the next thing a data-oriented node would remove. |
| p-t-ffi: the desktop shell's FFI shapes against a stub C library (`p-t-ffi.c`, `p-t-ffi.ffi.json`, declarations in `p-t-ffi.decl.ts`): a `pointer` handle as a bigint, `string` parameters as `(ptr, len)` including the empty one, a retained `cstring` callback with a context pointer fired from inside a later pump call driven by a timer chain, replies sent through a Promise after the pump returned, routes in a `Map` of functions, a release binding | PASS, fully static | The runner builds a probe's `.c` into `out/lib<name>.a` and passes `--ffi` when `<name>.ffi.json` exists, running such a probe natively only. A `declare function` imported from a `.ts` module binds; `Map<string, (args: unknown[]) => Promise<unknown>>` works; `JSON.parse` output narrows with `Array.isArray` and `typeof`. The shell's `host.js`, `ffi.ts` and bridge follow this probe. |
| p-u-crypto: `crypto.randomBytes(16).toString("hex")` | PASS, same output shape as node | The asset server's per-launch token comes from `randomBytes`. |
| p-v-http: `http.createServer` on a loopback port chosen by the system, `readFileSync` in the handler, `writeHead` with a content type and `Cache-Control`, a 404, `server.close()`, fetched by curl spawned with `child_process.spawn` (a synchronous client in the same process waits on its own server) | PASS with output identical to node, after two forms changed | The port is read as `server.address().port` directly, the form the compiler lowers; a cast or a `typeof` narrowing of the `string | AddressInfo | null` union is refused, so a `/* @ts-expect-error */` block comment (the form the lint rule allows) covers the node types. A stream's `data` listener is lowered only when its parameter is typed `Buffer` or `string` in TypeScript syntax, never from JSDoc, so the one listener lives in `p-v-http.read.ts`; the shell keeps stream readers in `.ts` helpers. |
| desktop shell (`native/desktop/`, no probe of its own): the demo backend and the harness's desktop backend compiled against the shim's manifest | fully static after two changes | A retained FFI callback must be the exact function value the manifest describes: `desktop_bind(w, name, this.onCall)` with the callback in a field was refused (SC5003, "an implicit function adapter would change its release identity"), so `host.js` binds one module-level `onCall` that routes to the active app. A route handler returning a `Promise` of an object literal type threw at the call natively ("invoked through a `(unknown) => Promise<unknown>` slot, the result cannot convert"), while `Promise<number>`, `Promise<string>` and `Promise<null>` converted; a handler types its value `unknown` before `Promise.resolve`. |
| p-w-sync-fs: `mkdirSync`/`rmSync` recursive, `readdirSync`, `statSync` fields, `renameSync`, `appendFileSync`, `unlinkSync`, `rmdirSync`, a Buffer read hashed, a failing `statSync` | PASS after two forms changed | `readdirSync(dir, { withFileTypes: true })` entries exist natively but their `isDirectory()` is not callable: list names and `statSync` each. A catch binding yields only `name` and `message` after `instanceof Error` (`"code" in e` is refused): an fs error's code is read from the message prefix (`ENOENT: …`), or avoided with `existsSync` first. |
| p-x-watch-many: 600 directories each under its own `fs.watch`, writes into two of them, a watched directory removed, every watcher closed, a write after the close | PASS (0.85 s natively, the same booleans as node) | An `FSWatcher` handle has no dynamic representation: it cannot sit in an array or a `Map`, nor inside a class instance that is pushed into one. Hold it in a closure (`closers.set(dir, () => watcher.close())`): functions convert into collection slots and keep identity. A `Map` of functions has no `size` natively; count while iterating. 600 watchers at once work, so a recursive watch is one `fs.watch` per directory. |
| p-y-json-shapes: a literal tree typed `unknown` stringified, a 5 MB document parsed and narrowed, a dispatcher class over `Map<string, (payload: unknown, meta: Meta) => Promise<unknown>>` with a `Meta` class, an async arrow handler, a throwing handler, a fallback field | PASS after two forms changed | `JSON.stringify` of a class instance is refused: copy its fields into a record typed `unknown` first. `map.get(type) ?? this.fallback` (two unions) has no layout: narrow the map's result with `!== undefined` before falling back. An arrow assigned straight to a nullable function field is inferred as `(unknown, unknown) => unknown`: assign it through a const typed `@type {Handler}`. Handlers in the map, `await handler(payload, meta)` in an async method, and the error envelope all compile. |
| p-z-spawn-kill: a `sleep 5` killed from a timer, a detached child `unref`ed, `execFileSync` of a missing binary, git through `spawn` with `cwd`, a stdout listener and the caller's own timeout | PASS after one form changed | `execFile` has no `cwd` (nor `timeout`) natively: a command with a working directory is `spawn(bin, args, { cwd, stdio })`, its output read by a `(chunk: Buffer)` listener in a `.ts` helper, its timeout a `setTimeout` that kills it. The exit listener `(code, signal)` also lives in the `.ts` helper. `kill("SIGTERM")`, `detached: true` + `unref()`, and a thrown `execFileSync` all match node. |
| p-aa-fetch: a local server answering text, bytes and a 404; `fetch` reads status, `text()`, `arrayBuffer()` into a Buffer, sees `ok === false`, rejects on an unreachable port, reaches `https://example.com` with `AbortSignal.timeout` | PASS, identical to node | The OTA updater's downloads go through `fetch` to a Buffer; https works natively. |
| p-ab-text: a `RegExp` from an escaped term with `gi` and `\b`, `replace`, `test` with `lastIndex` reset, `localeCompare` in a sort, `split`, URI encoding, a fixed ISO date, `parseInt`, `padStart`, `Object.entries`/`fromEntries`, the `path` functions | PASS, identical to node | The search, replace, tree and path-guard code keeps its node shape. |
| p-ac-process: argv, env, platform, execPath, pid, cwd, home and temp directories, an `exit` listener, a `SIGTERM` handler reached by `process.kill(process.pid)` | PASS, identical to node | Signal handlers and `process.exit` from them work natively. `process.argv[0]` natively is not the executable's path (p-ad found `scriptc` there): a program that relaunches itself uses `process.execPath`. |
| p-ad-stdin-lines: the probe spawns itself behind a `printf` with `--child` and the child answers each NDJSON stdin line on stdout (`process.stdin.on("data", (chunk: Uint8Array) => …)` + `TextDecoder` in a `.ts` helper) | PASS, identical to node | A host without a window can carry its envelopes over stdin and stdout. The stdin listener's parameter is typed `Uint8Array` in TypeScript syntax; `process.stdin.resume()` is not in scriptc's bundled types (light's terminal compiles it with `@types/node` present). |
| p-g1 … p-g4: JavaScript generic classes | one generic class: PASS; **a generic subclass of a generic class: ICE** ("generic family has an incompatible prefix"); a generic subclass of a non-generic base: PASS; composition: PASS | `Computed` must not extend `Signal`; both extend `Dep`. Light's structural `Reactive` interface casts (`/** @type {Reactive} */ (this)`) compile to deferred throws ("opaque structural views"), so `Reactive` becomes a class. |
| p-c (in the harness, `probes/p-c-*`): a TypeScript program importing light's JavaScript by relative path and through a tsconfig `paths` alias | both resolve as program modules; `paths` is scriptc-only (node needs an import map) | The harness imports light by relative path. Any light file imported pulls in everything its `types.ts` references, so shared type files must not reference host modules (`html/types.ts` currently reaches `slots.js`). |
| harness probes p0–p31 on 0.2.10 | identical pass/fail set to 0.2.9 | light pins scriptc 0.2.10; the harness upgrades when it switches to light. |

Rules carried over from the harness (`writting-harness/probes/README.md`): no recursive array unions in TypeScript, never `instanceof` on a union with an array arm, a function-typed field must not share a name with any method in the program, `Set` of functions is rejected (arrays are fine).

Rules the terminal port added: a listener typed with `Buffer` cannot be invoked through a slot the compiler typed loosely ("a '(Uint8Array) => void' function invoked through a '(unknown) => void' slot"), so the terminal's input listeners are typed `Uint8Array`, and a TypeScript program that registers one types the parameter `unknown` and narrows with `instanceof Uint8Array`, since a function it types `Uint8Array` is still refused by that slot (the harness's `demo-static.ts` shows the form); `node:string_decoder` has no static form (`tdom/input.js` carries its own UTF-8 decoder); a stored `setTimeout` handle is `unknown` (keep a flag and a generation counter instead); an empty `new Map()` needs its type written where a `Map<string, unknown>` is expected; `String(object)` is unsupported, so `stringify` calls the object's own `toString` through `typeof`.
