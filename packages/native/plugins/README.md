# @light/plugins

The embedded JavaScript an app's user plugins run in, and nothing of the app's own protocol: `JsEngine` (`engine.ts`) is one QuickJS context, evaluating a source as a script, invoking a function by the id the app's prelude gave it, running the promise jobs, and answering a plugin's `__host(name, json)` through the `HostHandler` the app provides (a `Bridge` is the app's side, calling back into the plugins); every value crosses as text, JSON by convention, and a call past its time budget is stopped. `PluginProcess` (`process.ts`) is a child process a plugin spawned, its output batched in frames. `PluginSource` and `sourcesIn` (`sources.ts`) are a plugin's code with the file it came from, and a folder's `.js` files. `buildPrelude` (`prelude.ts`) is the JS side of an app's plugin API: the global its plugins call with `plugin(def)`, `util` and `theme`, the function table the core invokes by id, and `call` into the core; the app brings its name, its theme and the namespaces of its api, as `PreludePart`s (`namespacesOf` joins them) or as text.

`native/` holds the C shim (`wcjs.c`), the build of the archive (`build.sh`, run as the package's prepare step: scriptc's vendored quickjs-ng with its regex and Unicode symbols renamed apart from the runtime's own copy, into `native/out/libwcjs.a`), the FFI manifest an app links (`ffi.json`, named by the app's `native.ffi` and by a test's `// ffi:` header as `@light/plugins/native/ffi.json`) and `wcjs-node.mjs`, the same calls on node's engine for the tests.

Tests: `test/engine.test.ts` and `test/prelude.test.ts`, under node (the stand-in preloaded) and natively (`light-native test plugins`).
