# @lightstart/design

A project's design canvases: the screens under `design/<canvas>/` that an owner reviews, built, previewed, served and rendered to PNG by `light design`. A canvas is the format claude.ai's canvas reads: a `canvas.json` index of each board's file, place and size, its notes, and the `*.dc.html` boards themselves.

```bash
light design                  # list the canvases under design/
light design mobile           # build, then serve the local preview
light design mobile --build   # build only
light design:build [canvas]   # build one canvas or all of them
light design:serve <canvas> [--port 5097] [--host 127.0.0.1]
light design:render <canvas> [board...]
```

A project declares the package in `devDependencies`. The CLI discovers `cli/commands/design*.ts` from `node_modules`, so no registration is needed.

## A canvas

```
design/<canvas>/
├── build.mjs          # writes the boards, canvas.json and canvas/project
├── directions.mjs     # the bands, boards and notes (or boards.mjs plus a shell)
├── assets.json        # uploaded photo addresses, when the canvas has photos
└── preview.html       # generated by the CLI, not edited
```

`light design:build` finds each folder under `design/` with a `build.mjs`, runs `node build.mjs` in it, then writes `preview.html` from the index the build wrote. The index may sit at `canvas.json` or `canvas/project/canvas.json`; the preview prefixes the iframes with the right base in either case.

`canvas/project/` is the published tree. Its files are staged by the project's build, never by this package.

## The band layout

A build composes its canvas with `layoutCanvas(dir, { title, bands })`. Each band is a title, an optional date, a note, and its boards in a row; a board is `{ file, title, w, h, html, note? }`. It writes each board's HTML, the `canvas.json` index and a `BOARDS.md` listing the bands and boards.

```js
import { layoutCanvas } from "@lightstart/design";

layoutCanvas(".", {
  title: "Mobile",
  bands: [
    {
      title: "The language",
      date: "Nov 21",
      note: "What the screens share.",
      boards: [
        { file: "Home.dc.html", title: "Home", w: 390, h: 844, html: home(), note: "The first screen." },
        { file: "Account.dc.html", title: "Account", w: 390, h: 844, html: account() },
      ],
    },
  ],
});
```

The gaps and note measurements are the layout's defaults; `LayoutOptions` overrides them (`gap`, `bandNoteWidth`, `bandGap`, `noteMinWidth`, `noteMaxWidth` and the rest).

## Rendering

`light design:render <canvas> [board...]` screenshots each board of the canvas's `canvas.json` at its own width and height into `design/renders/<canvas>/<board>.png`, the board named by its file without `.dc.html`. Naming boards renders only those. Playwright is resolved from the project first and from beside light second, the way the build's prerender resolves it; a missing install fails naming `playwright` and `npx playwright install chromium`.

The planning step is separate from the screenshot: `planRenders(projectDir, canvas, index, only)` answers the boards and their PNG paths, and `renderPlan(plan)` opens the browser.

## The serve hook

`light serve` starts every canvas at `http://localhost:5097/`, or the next free port, through `cli/hooks/serve.after.ts`. The index links each canvas; a missing `preview.html` is written from the built `canvas.json`. An ephemeral server (a build, a test run, the desktop shell) skips it. The hook reads `ServeAfterPayload` from `@lightstart/dev`: `projectDir`, `port`, `ephemeral` and `origins`, using `origins.lan` when the dev server also answers on the LAN.

## Publishing

Publishing belongs to the agent session with the review tools: read the live `project/canvas.json`, port the owner's edits into the source, build, then publish the changed files. This package stops after the build because the CLI has no review-tool access.

The `design-canvas` skill carries the full workflow.

## Node-only

The package is node-only: it runs a canvas's build, reads and writes the disk, serves files and screenshots with Playwright. The preview page, the band layout's measurements and the render plan are pure functions, but the package as a whole has no browser or native entry.
