# Working on @lightstart/design

What the package is and how to use it: [README.md](README.md). This file is what a change to it has to keep.

## Layout

| Where | What |
|---|---|
| `index.ts` | The public entry: the canvas, layout, preview, render and serve exports, and the types |
| `canvas.ts` | `canvasNames`, `canvasDir`, `readCanvasIndex`, `writePreview`, `buildCanvas`, `canvasInfo` |
| `layout.ts` | `layoutCanvas`: a canvas in bands, its boards, `canvas.json` and `BOARDS.md` |
| `preview.ts` | `previewPage`: the local layout of the index, each board in an iframe, the notes, the zoom |
| `render.ts` | `planRenders`, `renderPlan`, `renderCanvas`, `chromiumFrom`: the board selection, the Playwright PNGs |
| `serve.ts` | `serveCanvas`, `serveCanvases`, `listenCanvas`, `listenCanvases`, `serveUntilSignal`: the static preview server |
| `types.ts` | `CanvasIndex`, the board and note records, `LayoutCanvas` and `LayoutOptions`, `RenderPlan`, `ServeOptions` |
| `cli/commands/design.ts` | `light design`: list the canvases, or build one and serve it |
| `cli/commands/design/build.ts` | `light design:build [canvas]` |
| `cli/commands/design/serve.ts` | `light design:serve [canvas] [--port] [--host]` |
| `cli/commands/design/render.ts` | `light design:render <canvas> [board...]` |
| `cli/hooks/serve.after.ts` | `serve:after`: start every canvas beside `light serve`, write a missing preview, close at shutdown |
| `skills/design-canvas.md` | The agent workflow: add a screen, build, preview, render, publish |
| `test/` | Plain scripts on `@lightstart/test/assert.ts`; the disk and server tests start with `// node-only` |

## Rules the sources keep

- A canvas is a folder under a project's `design/` with a `build.mjs`; its source is whatever that build reads (bands in the build itself through `layoutCanvas`, or files beside it). `canvas.json` is the index: boards by file with `x`, `y`, `w`, `h` and a title, and the notes. The build may keep it at the canvas root or under `canvas/project`; `readCanvasIndex` answers its base prefix so the preview and the render read the right files.
- `light design:build` runs `node build.mjs` in the canvas folder, then writes `preview.html`; the preview and the index are never edited by hand.
- `layoutCanvas` keeps the band layout's numbers: a 120 px gap between boards, a 900 px band note 80 px under the band title, 70 px from that note to the boards, 30 px from a board to its note, a 220 px gap between bands, and notes 360–620 px wide. `LayoutOptions` overrides them; the defaults do not move. It merges a previous `canvas.json` so `launch`, `pages`, `designSystems` and other unknown fields survive.
- `BOARDS.md` and `canvas.json` are generated by `layoutCanvas`; a canvas whose build lays itself out writes the same shapes.
- `light design:render` reads `canvas.json` and screenshots every board, or the boards named, at the board's own width and height into `design/renders/<canvas>/<board>.png`. Playwright is the project's, else the one beside light, through `chromiumFrom`; a missing install fails with the install lines. The selection is `planRenders`, kept separate so a test can check it without a browser.
- `serveCanvas` answers `/` with `preview.html` and every other path with a file under the canvas, refusing a path that leaves the folder. `serveCanvases` lists every canvas at `/` and serves each at `/<canvas>/`; the list is read per request, so a canvas added while the server runs appears. The port starts at the asked one and takes the next 19 when busy; port 0 asks the system.
- The `serve:after` hook reads `ServeAfterPayload` from `@lightstart/dev` and uses only its fields: `projectDir`, `port`, `ephemeral` and `origins`. It skips an ephemeral server and binds `0.0.0.0` when `origins.lan` is present. It returns the server's close as its teardown.
- The package is node-only. Tests are plain scripts on `@lightstart/test/assert.ts`; a test that touches the disk, spawns a build or serves a port starts with `// node-only`.
- Comments are a JSDoc module header and JSDoc on exported symbols, nothing else.
- TypeScript with erasable syntax only; the package ships its sources and needs no build step.

## Contracts others depend on

| Contract | Who relies on it |
|---|---|
| `canvas.json` as `{ title, boards: Record<file, { x, y, w, h, title? }>, notes: Record<key, { x, y, w?, maxW?, text, kind? }> }`, at the canvas root or `canvas/project` | a canvas's own `build.mjs`, `previewPage`, `planRenders`, the `serve:after` hook, and claude.ai's canvas |
| `build.mjs` writing the boards and the index in the canvas folder | `buildCanvas` and `light design:build` |
| `preview.html` as a generated local layout, never edited | `light design`, `light design:serve` and the serve hook |
| `layoutCanvas(dir, { title, bands }, options?)` writing boards, `canvas.json` and `BOARDS.md`, and answering the board count | a canvas's `build.mjs` |
| `design/renders/<canvas>/<board>.png`, named from the file without `.dc.html` | the review workflow and the render command |
| The `serve:after` hook and its `ServeAfterPayload` fields (`projectDir`, `port`, `ephemeral`, `origins.lan`) | `light serve` and the canvas server it starts |
| The commands `design`, `design:build`, `design:serve`, `design:render` and their flags | projects that declare `@lightstart/design` |

## Gates

From the repository root:

```bash
light check --all
light typecheck @lightstart/design
npx eslint packages/design
light test @lightstart/design     # node and native where the test allows it
```

`light design:render` needs Playwright and Chromium; the tests plan a render and never launch the browser.
